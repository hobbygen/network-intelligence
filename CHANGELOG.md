# Changelog

## Unreleased

- Fix per-application traffic attribution merging two different processes' bytes when the Windows kernel reuses a pid inside one 5-second ETW collection window (`docs/DECISIONS.md` ADR-018) — the one gap ADR-012 left open. A new pure `ProcessTrafficAccumulator` (`NetworkIntelligence.Domain`) detects the handoff at the process-start event and splits pending traffic by identity before it's aggregated, instead of merging it under whichever name is current at flush time. No schema change; storage, baselines and export already handled multiple differently-named samples per pid correctly. 6 new tests (138 total) — this scenario can't be reliably forced live, so the pure extraction is the only way to verify it deterministically. Scoped narrower than full executable-path identity, which remains out of scope.

- Add a dedicated, browsable/filterable alert history page (`docs/DECISIONS.md` ADR-017): a new "Alert history" nav item lists up to the last 200 stored `AnomalyEvent` rows (newest first), independent of the Dashboard's live, capped-at-50 "Recent alerts" card, with process-name search, severity and direction filters (all client-side, view-only) and a manual refresh. No schema change — reuses the existing `AnomalyEvents` table and `GetAnomalyEventsAsync`. Wired into history deletion (previously the delete-history dialog didn't mention it, though the table was already cleared).

- Persist completed speed-test runs, database schema version 4 (`docs/DECISIONS.md` ADR-016): a new `SpeedTests` table (JSON rows, following the `Diagnostics` table's pattern) stores timestamp, endpoint and every result metric for a run that finishes successfully — cancelled, failed or timed-out runs are never written, matching `TransferTest`'s own "incomplete results are discarded" contract. Network performance gained a "Recent speed tests" card showing the last 10 runs, reloaded on startup, on history refresh, and immediately after a new run completes. Wired into the existing retention/deletion paths alongside adapter, diagnostic, application and anomaly history. 3 new tests (132 total).

- Finish usage reports on Bandwidth and data: daily, Monday-based weekly, monthly, yearly and custom calendar ranges, daily charts and coverage, separate adapter totals, top applications across all interfaces, and snapshot-consistent CSV/JSON export. Missing measurements remain unavailable; overlapping coverage is flagged. Add the yearly preset and year-boundary/leap-year/history-deletion tests. See ADR-015.

- Add one-click Internet speed testing with automatic Cloudflare selection, saved custom HTTPS provider override, same-page Cancel, stage/download progress, and download/upload/HTTP latency/jitter results. Tests remain manual and bounded to 25 MB download + 10 MB random upload with a 60-second deadline. Reject incompatible/incomplete responses, distinguish cancellation from timeout, and handle rate limiting without automatic retries. See ADR-014.

- Add a real application icon, generated as a multi-resolution (16–256px) `.ico` from a supplied source PNG, embedded in the exe (`ApplicationIcon`) and set at runtime on both the main window (`AppWindow.SetIcon`) and the tray icon (previously a generic system stock icon), each degrading to the prior fallback if the icon file is ever missing rather than failing. Set `Authors`/`Company`/`Product`/`Copyright` MSBuild properties crediting Naeem Ahmad, and added an "About" page (`NavigationView.FooterMenuItems`, positioned directly above Settings) showing the icon, version (read from the assembly, not hardcoded), a description and "Created by Naeem Ahmad."
- Fix the light/dark theme toggle: it only ever applied on clicking "Save settings," and that save's `Validate()` covers several unrelated fields (diagnostic target, anomaly sensitivity, retention) whose failure silently blocked the theme change too, with only an easy-to-miss status-bar message. Diagnosed by proving `Root.RequestedTheme` itself re-themes correctly at runtime (confirmed via a temporary forced-dark smoke-test render, since removed) before concluding the bug was in the save flow, not the theme API. `ThemePicker` now applies and persists the theme immediately on selection, independent of the other Settings fields; a new `applyingSettings` guard prevents the resulting `SelectionChanged` from re-firing when the picker's own index is set programmatically (on load, and after a real Save).

- Validate the ETW kernel Network provider as the Tier-3 per-application telemetry mechanism: standard-user permission-denied path and an elevated capture (0 events lost, real per-process TCP/UDP byte totals, IPv4/IPv6, header-only) — see `docs/ETW_VALIDATION.md`.
- Add the `NetworkIntelligence.MonitoringService` scaffold: a Generic Host worker (runnable as a plain elevated console process or installed as a Windows Service, `StartupType Manual`) hosting a continuous kernel-ETW collector and a named-pipe IPC server with a restrictive ACL, versioned/bounded message framing, and audit-logged client identity. Validated end to end manually. Add install/uninstall/local-run scripts and 6 wire-format unit tests.
- Add a controlled-traffic accuracy test (`--accuracy-test-mib`): sends an exact, independently-tallied 1 MiB / 100 MiB over a loopback socket and compares against the service's ETW attribution — 0% delta both directions, both sizes, 0 events lost (see `docs/ETW_ACCURACY.md`). Narrow scope (loopback, single process).
- Wire the MonitoringService client into the app (`docs/DECISIONS.md` ADR-009): a new `IApplicationTrafficClient`/`MonitoringServiceClient` polled on its own independent 4-second timer, and a "Live per-application bandwidth (optional)" card on the Application Usage page that shows real data when the service is running and degrades to "Unavailable" (never fake data) otherwise. Verified visually via an extended `--smoke-test --smoke-page <name>` flag in both states.
- Persist per-application traffic as minute aggregates, database schema version 2 (`docs/DECISIONS.md` ADR-010): a new `ApplicationTrafficMinutes` table following the same aggregation pattern as adapter history, wired into the existing retention/deletion/export paths, with a "Stored per-application history" card and CSV/JSON export on the Application Usage page. 4 new tests (32 total).
- Add algorithmic anomaly detection, database schema version 3 (`docs/DECISIONS.md` ADR-011): `BaselineCalculator` (Welford mean/stddev with outlier trimming) and `AnomalyEvaluator` (pure, per-direction) in Domain; `AnomalyTracker` (sustained-duration + cooldown state machine) and `AnomalyDetectionService` (orchestration, downstream of the live application-traffic poll) in Application. Learns per-process-name baselines from stored history, requires a 60-sample/7-day learning period before any alert, evaluates download/upload independently, excludes trusted apps, persists fired anomalies to a new `AnomalyEvents` table, and notifies via tray (gated by quiet hours/alerts-enabled, which never gates storage). Adds a "Trust this app" button, a Dashboard "Recent alerts" card, and a Settings sensitivity control. 29 new tests (61 total) covering every required scenario from requirements section 16.4; caught and fixed a real double-counting bug in multi-process baseline rate computation along the way. Detection thresholds are provisional, not validated against a real false-positive rate; stable application identity, alert snooze/history browsing and health scoring remain outstanding.
- Fix restart-attribution gap in per-application identity (`docs/DECISIONS.md` ADR-012): `EtwCollector` now resolves process names from kernel `ProcessStart`/`ProcessDCStart` rundown events, captured at/near a process's actual start, instead of a live `Process.GetProcessById` lookup at window-flush time (up to 5s later) — previously any process that had already exited by then fell back to a PID-embedded placeholder that differed on every restart, so restart-prone short-lived processes could never accumulate the baseline learning period under one stable name and stayed permanently exempt from anomaly detection. Stopped-process entries are retained 2 minutes past their stop event then pruned, bounding memory under process churn. Solution builds clean and the existing 61-test suite is unaffected (no test project covers `MonitoringService`). Live-validated elevated via `scripts/service-run-foreground.ps1`: kernel session started cleanly with the added Process provider, 0 events lost; 15 concurrent short-lived `curl.exe` processes (each ~1-2s) were correctly attributed by name over the pipe, not as PID-exited placeholders — the specific failure mode this fixes.
- Add untrust to the Settings trusted-applications list (`docs/DECISIONS.md` ADR-011 follow-up): the trust list was previously a view-only comma-joined line. It's now an `ItemsControl` with a per-row "Untrust" button that removes the app case-insensitively and saves through the same settings round-trip trust/save already use, taking effect on the next detection cycle without an app restart. Visually verified via `--smoke-test --smoke-page Settings` against a seeded trusted app.
- Add snooze and dismiss to the Dashboard "Recent alerts" card (`docs/DECISIONS.md` ADR-011 follow-up), closing requirements section 10.6's last unimplemented alert action. `AnomalyTracker` gained a temporary, unpersisted per-(process,direction) snooze, separate from both its existing automatic cooldown and from permanent trust — a snoozed firing doesn't consume the cooldown, so an anomaly already sustained through the snooze period fires immediately once it lapses. "Snooze 1h" and "Dismiss" both remove the alert from view only; the stored evidence row is never touched by either. 2 new `AnomalyTracker` tests (63 total). Visually verified via `--smoke-test --smoke-page Dashboard` against a seeded anomaly event.
- Add the network health score (`docs/DECISIONS.md` ADR-013), closing requirements section 12.4 — the last entirely-unbuilt Dashboard element. A new, pure `HealthScoreCalculator` in Domain scores up to 8 factors (connectivity, latency, packet loss, jitter, DNS response, Wi-Fi signal, adapter errors, recent disconnects) on a documented 0-100 scale and combines only the currently-available ones as a weighted average — an unmeasured factor (most commonly: no Diagnostics run yet, or a stale one older than 30 minutes) is excluded rather than assumed or defaulted, and the Dashboard's new "Network health" card shows the score, band and every factor's own detail transparently. Caught and fixed a real bug along the way: WLAN interface GUIDs come back brace-wrapped while `NetworkInterface.Id` doesn't have braces, so the Wi-Fi signal factor was silently never matching a real Wi-Fi adapter until the IDs were normalized before comparing. 12 new tests (75 total); visually verified via `--smoke-test --smoke-page Dashboard` against this machine's live Wi-Fi connection. Weights and scoring curves are a provisional first pass, not validated against measured user-perceived quality.
